## เปิดดูเว็บ

เปิดไฟล์ `index.html` ด้วยเบราว์เซอร์ได้เลย หรือรัน local server:

```bash
node .claude/serve.js
```

แล้วเปิด http://localhost:8756 — หลังบ้านอยู่ที่ http://localhost:8756/admin

หมายเหตุ: เปิดไฟล์ HTML ตรง ๆ (file://) เนื้อหาจากฐานข้อมูลจะโหลดไม่ได้เพราะติด CORS
จะเห็นเป็นเนื้อหาสำรองที่ฝังในไฟล์แทน ให้รันผ่าน server เสมอ

## แก้ข้อความ / คำแปล

ข้อความทุกคำอยู่ใน `assets/js/i18n.js` เป็นคู่ EN/TH เช่น

```js
en: { "hero.text": "Twenty years behind the kit ..." }
th: { "hero.text": "ประสบการณ์หลังกลองยี่สิบปี ..." }
```

ใน HTML ผูกด้วย attribute:

| attribute | ใช้กับ |
|---|---|
| `data-i18n="key"` | ข้อความปกติ |
| `data-i18n-html="key"` | ข้อความที่มีแท็กข้างใน |
| `data-i18n-ph="key"` | placeholder ของ input |
| `data-title-en/th` (บน `<body>`) | `<title>` ของหน้านั้น |

**สำคัญ:** ทุก key ต้องมีครบทั้ง `en` และ `th` (ตอนนี้มี 254 key ครบทั้งสองภาษา)
ภาษาที่เลือกถูกจำไว้ใน `localStorage` และครั้งแรกจะเดาจากภาษาของเบราว์เซอร์

### อัปโหลดวิดีโอ

ในฟอร์มเพิ่ม/แก้บทเรียน ช่อง **วิดีโอ** ทำได้ 2 แบบ

1. **อัปโหลดไฟล์** — กด "เลือกไฟล์วิดีโอ" เลือก mp4 / webm / mov ขนาดไม่เกิน 50 MB
   ระบบอัปขึ้น Supabase Storage พร้อมแถบความคืบหน้า เสร็จแล้วเติมลิงก์ให้อัตโนมัติ
   และแสดงตัวอย่างให้ดูก่อนกดบันทึก
2. **วางลิงก์** — YouTube / Vimeo หรือลิงก์อื่น ๆ พิมพ์ลงช่องได้ตรง ๆ

บนหน้าเว็บ:

- ไฟล์ที่อัปโหลดเอง (mp4/webm/mov) → กดการ์ดแล้ว **เล่นในหน้าเลย** (lightbox ปิดด้วยปุ่ม × หรือ Esc)
- ลิงก์ภายนอก → เปิดแท็บใหม่
- บทเรียนที่ยังไม่มีวิดีโอ → การ์ดแสดงปกติ กดไม่ได้ (ไม่มีลิงก์เสีย)

ในตารางหลังบ้านมีคอลัมน์ **วิดีโอ** บอกว่าบทไหนแนบไฟล์แล้ว กดที่ป้ายเพื่อเปิดดูไฟล์ได้

**เปลี่ยน/ลบไฟล์:** อัปไฟล์ใหม่ทับ ระบบลบไฟล์เก่าออกจากที่เก็บให้เอง (ไม่ปล่อยขยะค้าง)
หรือกดปุ่ม "ลบวิดีโอ" เพื่อลบไฟล์ถาวรแล้วเคลียร์ช่อง

**ข้อจำกัดของ Supabase แผนฟรี**

| | |
|---|---|
| ขนาดไฟล์ต่อไฟล์ | 50 MB (ระบบเช็คให้ก่อนอัป ถ้าเกินจะเตือน) |
| พื้นที่รวม | 1 GB |
| แบนด์วิดท์ | 5 GB / เดือน |

วิดีโอสอนกลอง 10 นาทีคุณภาพปกติมักเกิน 50 MB — ถ้าคลิปยาว แนะนำ **อัปขึ้น YouTube
แบบ unlisted แล้ววางลิงก์แทน** จะไม่กินโควตาและสตรีมลื่นกว่า ส่วนการอัปไฟล์ตรง
เหมาะกับคลิปสั้น ๆ เช่นตัวอย่างจังหวะหรือแบบฝึกหัดสั้น

### ทำงานยังไง

- หน้าเว็บโหลดเนื้อหาจาก Supabase ตอนเปิดหน้า ถ้าต่อฐานข้อมูลไม่ได้
  จะใช้เนื้อหาสำรองที่ฝังอยู่ในไฟล์ HTML แทน — **เว็บไม่มีทางขาวทั้งหน้า**
- แก้ในหลังบ้าน → กด refresh หน้าเว็บ → เห็นผลทันที ไม่ต้อง deploy ใหม่

### ความปลอดภัย — อ่านให้จบ

สิ่งที่ทำไว้แล้ว:

- ทุกตารางเปิด **RLS** — anon key ที่ฝังในหน้าเว็บ **อ่านได้อย่างเดียว** และอ่านเฉพาะแถวที่เผยแพร่
- การเขียน/ลบทั้งหมดวิ่งผ่านฟังก์ชัน `admin_*` ใน Postgres ที่**ตรวจ PIN ทุกครั้ง**
  ต่อให้ใครก๊อป anon key จากหน้าเว็บไป ก็เขียนอะไรไม่ได้ถ้าไม่รู้ PIN
- **PIN ไม่ได้ฝังอยู่ในโค้ดหน้าเว็บ** เก็บเป็น sha256 hash ในฐานข้อมูล ดู view-source ก็ไม่เจอ
- ใส่ PIN ผิดเกิน 10 ครั้งใน 15 นาที ระบบล็อกชั่วคราว
- PIN เก็บใน sessionStorage เท่านั้น (ปิดแท็บแล้วหลุด) และ auto-lock เมื่อไม่ได้ใช้งาน 30 นาที
- ตาราง `admin_config` (ที่เก็บ hash) anon อ่านไม่ได้เลย
- **การอัปโหลด/ลบวิดีโอก็ต้องใช้ PIN เหมือนกัน** — ตรวจที่ฝั่งเซิร์ฟเวอร์ผ่าน RLS ของ
  `storage.objects` (ทดสอบแล้ว: ไม่ส่ง PIN หรือส่งผิด → 403) และจำกัดไฟล์ในถังไว้ที่ 300 ไฟล์

สิ่งที่ยังเป็นข้อจำกัด — ควรรู้ไว้:

1. **PIN 6 หลักคือรหัสเดียวที่กั้นอยู่** ใครได้ PIN ไปก็แก้เนื้อหาได้ทั้งเว็บ
   ถ้าอยากได้ความปลอดภัยระดับจริงจัง ควรเปลี่ยนไปใช้ Supabase Auth (อีเมล+รหัสผ่าน)
   ซึ่งได้ทั้ง session token, การหมดอายุ และ log ว่าใครแก้อะไร
2. **ไฟล์ `Secret token.rtf` บน Desktop มีรหัสฐานข้อมูลกับ service_role key แบบข้อความเปล่า**
   — service_role key เปิดฐานข้อมูลได้ทั้งหมดโดยข้าม RLS **ห้ามเอาไปใส่ในเว็บเด็ดขาด**
   (ไฟล์ในเว็บใช้แค่ anon key เท่านั้น)
3. **รหัสฐานข้อมูลชุดปัจจุบันเดาง่ายและใช้ตัวเลขชุดเดียวกับ PIN** แนะนำให้เข้าไป
   Supabase → Settings → Database → Reset database password ตั้งใหม่ให้สุ่มและยาว
   แล้วรัน `python3 tools/make_config.py` ใหม่ (anon key ไม่เปลี่ยน ไม่ต้องแก้อะไรในเว็บ)

## Deploy (Cloudflare Pages)

เว็บอยู่ที่ **https://kru-liang-drums.pages.dev** — Pages project ชื่อ `kru-liang-drums`

### deploy ใหม่หลังแก้ไฟล์

```bash
python3 tools/build.py && python3 tools/make_dist.py
npx wrangler@4 pages deploy dist --project-name=kru-liang-drums --branch=main
```

ต้องตั้ง env 2 ตัวก่อน (ดูค่าได้จากไฟล์ key และ Cloudflare dashboard):
`CLOUDFLARE_API_TOKEN` และ `CLOUDFLARE_ACCOUNT_ID`

> เนื้อหาที่แก้จากหน้า /admin **ไม่ต้อง deploy ใหม่** เพราะดึงสด ๆ จาก Supabase
> จะ deploy ก็ต่อเมื่อแก้โค้ด/หน้าตา/ไฟล์รูปเท่านั้น

### อะไรขึ้นเว็บบ้าง

`tools/make_dist.py` จะคัดเฉพาะไฟล์ที่ต้องเปิดสาธารณะลงโฟลเดอร์ `dist/` (15 ไฟล์)
**ไม่เอาขึ้น:** `tools/` (มี path ของไฟล์ key), `supabase/` (SQL ภายใน), `README.md`,
`vercel.json` และไฟล์ note ต่าง ๆ — เช็คได้ว่าไม่หลุดจริงด้วย

```bash
grep -rl 'Secret token\|service_role\|postgresql://\|cfut_' dist/
```

### กับดักที่เคยเจอ (อย่าทำซ้ำ)

1. **ห้ามใส่กฎ `/admin -> /admin.html 200` ใน `_redirects`** — Cloudflare Pages ทำ clean URL
   ให้เองอยู่แล้ว (`/admin` เสิร์ฟจาก `admin.html`, ส่วน `/admin.html` เด้ง 308 ไป `/admin`)
   ถ้าเขียนกฎเองจะกลายเป็น redirect วนไม่รู้จบ
2. **ต้องมี `404.html` เสมอ** — ถ้าไม่มี Pages จะเสิร์ฟหน้าแรกพร้อมสถานะ 200
   ให้ทุก URL มั่ว ๆ ซึ่งเสียทั้ง SEO และทำให้คนสับสน
3. ลิงก์ภายในใช้แบบไม่มี `.html` (`/lesson` ไม่ใช่ `lesson.html`) จะได้ไม่โดน 308 ทุกครั้งที่กดเมนู
   — dev server ใน `.claude/serve.js` รองรับแบบเดียวกันแล้ว

## แก้ header / footer

header กับ footer ใช้ร่วมกันทั้ง 5 หน้า ถ้าจะแก้ให้แก้ที่ `tools/build.py`
(ตัวแปร `HEAD` และ `FOOTER`) แล้วรัน:

```bash
python3 tools/build.py
```

สคริปต์จะเขียนไฟล์ HTML ทั้ง 5 หน้าใหม่ทับของเดิม
(ถ้าแก้ HTML แต่ละหน้าโดยตรงก็ได้ แต่ต้องแก้ header/footer ให้ตรงกันเองทุกหน้า)

## ปรับสี / ฟอนต์

แก้ที่ `:root` ใน `assets/css/style.css`

```css
--bg: #101215;      /* พื้นหลังหลัก ดำอมเทา */
--surface: #191d22; /* พื้นการ์ด */
--gold: #c9a961;    /* สีทองหลัก */
--text: #ece9e3;
```

ฟอนต์: Playfair Display + Noto Serif Thai (หัวข้อ), Inter + IBM Plex Sans Thai (เนื้อหา)
โหลดจาก Google Fonts ใน `<head>` ของทุกหน้า
